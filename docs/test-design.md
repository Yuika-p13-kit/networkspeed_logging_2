# Network Speed Monitoring System テスト設計

## 0. フェーズ宣言
- 本ドキュメントはテスト設計フェーズの成果物。
- 要件を基準に設計し、実装内部ロジックの参照を前提にしない。

## 1. テスト目的
- 運用互換（リトライ / スケジュール / CSV フォールバック / 再投入）を最優先で検証する。
- DB 既存テーブル互換（`network_speed_measurements`）を維持していることを検証する。
- 読み取り専用 API / ダッシュボードで最新値と履歴が参照できることを検証する。

## 2. テスト対象
1. 設定層
2. 永続化層
3. CSV バックアップ層
4. 計測層
5. スケジューラ層
6. オーケストレーター起動順
7. 読み取り専用 API / ダッシュボード

## 3. 非対象
- DB スキーマ変更テスト（スキーマ変更自体が対象外）。
- 認証/認可テスト。

## 4. 前提データ・環境
- Python 3.11+。
- PostgreSQL に `network_speed_measurements` テーブルが存在。
- `database_info.txt` は `key=value` 形式（`host/database/user/password`）。
- CSV 退避ファイル名は `network_speed_backup.csv`。

## 5. テスト観点
- 互換性: テーブル名・カラム名・単位変換・device 既定値。
- 復旧性: 計測失敗時再試行、DB 障害時退避、再起動時再投入。
- 継続性: 単発障害で監視ループが停止しない。
- 参照性: API/ダッシュボードで最新/履歴が取得できる。

## 6. テストケース一覧（設計）

### 6.1 設定層
- TC-CFG-001: `database_info.txt` 正常読込
  - 入力: `host=...` `database=...` `user=...` `password=...`
  - 期待: 接続情報が欠損なく取得される
- TC-CFG-002: `database_info.txt` 不在
  - 入力: ファイルなし
  - 期待: 環境変数または既定値へフォールバック
- TC-CFG-003: 一部キー欠損
  - 入力: `user` 欠損
  - 期待: 欠損を検知し、起動失敗または補完規則どおりの動作

### 6.2 永続化層
- TC-DB-001: 計測結果 1 件挿入
  - 期待: `network_speed_measurements` に 1 行追加
- TC-DB-002: 最新 1 件取得
  - 期待: 最新 timestamp の行を返す
- TC-DB-003: 履歴 N 件取得
  - 期待: 指定件数以内かつ新しい順

### 6.3 CSV バックアップ層
- TC-BK-001: DB 書き込み失敗時に CSV 追記
  - 期待: `network_speed_backup.csv` に 1 行追加
- TC-BK-002: 起動時再投入（全件成功）
  - 期待: DB 反映後 CSV 削除
- TC-BK-003: 起動時再投入（途中失敗）
  - 期待: 失敗時点で CSV を保持し、再実行可能

### 6.4 計測層
- TC-MEAS-001: 1 回で成功
  - 期待: download/upload が Mbps 小数 3 桁で返る
- TC-MEAS-002: 一時失敗後に成功
  - 期待: 5 回以内の再試行で成功し処理継続
- TC-MEAS-003: 5 回連続失敗
  - 期待: 当該計測を失敗扱いにしつつプロセス継続

### 6.5 スケジューラ層
- TC-SCH-001: 分刻み設定
  - 期待: `:00/:10/:20/:30/:40/:50` に起動設定される
- TC-SCH-002: ジョブ内例外
  - 期待: 次回スケジュール実行に影響しない

### 6.6 オーケストレーター
- TC-ORCH-001: 起動時の再投入を先に実行
  - 期待: 通常スケジュール開始前に再投入処理を呼ぶ
- TC-ORCH-002: KeyboardInterrupt
  - 期待: DB 接続などのクリーンアップを実施して終了

### 6.7 API / ダッシュボード
- TC-API-001: `GET /api/latest`
  - 期待: 最新 1 件を JSON で返す
- TC-API-002: `GET /api/history?limit=100`
  - 期待: limit 以内の配列を返す
- TC-WEB-001: ダッシュボード表示
  - 期待: 最新値と履歴が描画される（読み取り専用）

## 7. 優先実行順
1. 復旧フロー（TC-BK / TC-MEAS / TC-SCH）
2. 互換性（TC-CFG / TC-DB）
3. API / ダッシュボード（TC-API / TC-WEB）

## 8. 受け入れ判定
- 重大 (Blocker)
  - 計測失敗時にプロセス停止する
  - DB 障害時に CSV 退避されない
  - 起動時再投入後に CSV が不正に残る/消える
- 主要 (Major)
  - スケジュール時刻が 10 分刻みでない
  - Mbps 変換・丸めが要件不一致
- 軽微 (Minor)
  - ログ文言や表示フォーマット差異

## 9. 次フェーズへの引き継ぎ
- 実装フェーズでは本設計書の TC-ID を単位に、最小実装→単体検証の順で進める。
- テスト実行フェーズでは、実装参照を避けて期待値ベースで結果判定する。
